# Summary

The request presents a detailed specification for creating an architecture diagram for a long-document reranking demo built on Elastic Cloud Serverless, the `text_similarity_reranker` retriever with `chunk_rescorer`, and the Elastic Inference Service.

**Primary Focus:** Visualize the two-layer retriever pipeline where "a Jupyter notebook issues a single search request against a product-manuals index in Elastic Cloud Serverless, and a reranker retriever wrapping a filtered BM25 retriever returns the one manual whose troubleshooting section fixes the customer's symptom." The subject of the demo is the `chunk_rescorer` step inside the reranker retriever: on the shard, each manual is split into 300-word chunks, every chunk is scored lexically against the query, and only the best chunk per manual is sent to the reranker. Without it the reranker receives whole manuals and reads only the first 8,192 tokens of each; the troubleshooting section starts past that point in every long manual. The diagram must make the chunking step structurally obvious as a stage between the index and the inference service.
